# Эксперименты Java Memory Model

Эксперименты находятся в модуле `jcstress` общего Maven-проекта, рядом с модулем приложения
`advanced`. После импорта корневого pom.xml IDEA видит оба модуля. Исходники в
`jcstress/src/main/java/academy/backend/market_pulse/jmm` — jcstress-опыты, не JUnit-тесты:
обычный `mvn test` компилирует их, но не запускает стресс-эксперименты. Раннер запускается явно.
Выделенный модуль позволяет не добавлять зависимости и сгенерированные раннеры в приложение.

## Сборка и запуск

Из корня advanced-репозитория:

```bash
mvn -pl jcstress -am package -DskipTests
cd jcstress
java -jar target/jcstress.jar -t 'academy.backend.market_pulse.jmm.*' -m quick -f 1 -iters 2 -time 100 -c 2 -hs 128 -af NONE -jvmArgs '-Xms128m -Xmx128m' -r results
```

Для более длинного исследования увеличить iters/time/forks либо использовать `-m default` без
ограничивающего набора параметров. Короткая команда — воспроизводимая проверка и материал для
показа, не доказательство отсутствия запрещённых исходов. jcstress использует локальный сокет
связи с дочерними JVM, поэтому не запускать внутри среды, запрещающей открывать порты.

Версия jcstress — 0.16; модуль наследует JDK/release 25 и настройки компилятора из корневого pom.xml.
Heap начальный и максимальный согласованы: это важно для forked JVM. `-af NONE` отключает
привязку CPU, недоступную на части ОС. Аппаратная архитектура влияет на наблюдаемые частоты.

## Набор опытов

| Тест                | Вопрос                                                  | Допустимые исходы           |
|---------------------|---------------------------------------------------------|-----------------------------|
| DekkerPlain         | Две записи и два чтения без синхронизации               | (0,0), (0,1), (1,0), (1,1)  |
| DekkerVolatile      | Тот же алгоритм на volatile                             | Все предыдущие, кроме (0,0) |
| PublicationPlain    | Можно ли увидеть флаг без данных?                       | -1, 0, 42                   |
| PublicationVolatile | Публикует ли volatile-флаг предшествующие записи?       | -1, 42; 0 запрещён          |
| IncrementPlain      | Атомарен ли ++?                                         | 1 или 2                     |
| IncrementVolatile   | Делает ли volatile составной ++ атомарным?              | 1 или 2                     |
| FinalPublication    | Что гарантирует корректно сконструированное final-поле? | -1 или 42; 0 запрещён       |

В Publication* читатель делает одно чтение флага, без бесконечного spin. -1 означает, что флаг
не наблюдался. В Increment* счётчик читается в Arbiter после обоих Actor. В FinalPublication
конструктор не публикует this и поле после конструктора не изменяется.

Полный HTML-отчёт создаётся командой выше в `jcstress/results/index.html`.
Генерируемые HTML-отчёты, логи и сырые результаты в Git не храним; перед семинаром их нужно
подготовить запуском тестов. Числа выше оставлены как пример наблюдений конкретного запуска.
Сравнивать частоты между тестами как бенчмарк нельзя. JMH здесь не применяется: исследуем
допустимые исходы, а не стоимость операций.

## Порядок демонстрации

1. Показать только поля и Actor, попросить предсказать результаты.
2. Сформулировать разрешённые и запрещённые исходы до просмотра отчёта.
3. Короткий живой запуск — один опыт; долгие серии подготовить до занятия.
4. Сопоставить обычные и volatile-поля; разобрать конкретную цепочку happens-before.
5. Обсудить, почему «у меня не воспроизвелось» не доказывает корректность.

Референсы: статья https://habr.com/ru/articles/685518/ и JLS 17.4–17.5.


## Стек задач сквозного примера

`TreiberPushPlain` намеренно выполняет неатомарный `head = new Node(task, head)`.
Два actor могут потерять один push; arbiter проверяет наличие двух задач маской 3.
`TreiberPushCas` использует AtomicReference и повтор CAS, потеря задачи запрещена.
Это опыт атомарности: volatile-head без CAS не исправляет составную операцию.
Для отдельной демонстрации публикации/видимости по-прежнему использовать PublicationPlain/Volatile.
Фильтр запуска: `academy.backend.market_pulse.jmm.TreiberPush.*`. Редкий исход не обязан
появиться в коротком запуске; заранее подготовить отчёт.


## Проверка онлайн-материалов 2026-11-08

Запуск в `market-pulse-online` на macOS aarch64, JetBrains Runtime 25.0.3.
Из корня репозитория собрать модуль командой выше, затем из `jcstress`:

```bash
java -jar target/jcstress.jar -t 'academy.backend.market_pulse.jmm.*' -m sanity -f 1 -iters 1 -time 50 -c 2 -hs 128 -af NONE -jvmArgs '-Xms128m -Xmx128m' -r results
```

Все 9 опытов завершились без failed/error. Наблюдения, суммарно по конфигурациям:

| Опыт | Интересный исход | Число наблюдений |
|------|-----------------|-----------------|
| DekkerPlain | (0, 0) | 899 |
| IncrementPlain | итоговый счётчик 1 | 1 440 |
| IncrementVolatile | итоговый счётчик 1 | 1 101 |
| TreiberPushPlain | маска 1: потерян второй push | 23 767 |
| TreiberPushPlain | маска 2: потерян первый push | 7 015 |

В `PublicationPlain` интересный исход в этой короткой серии не встретился; это не делает
обычный флаг корректным средством публикации. Частоты относятся только к этому запуску:
режим sanity проверяет работоспособность опытов, а не доказывает корректность реализации.
